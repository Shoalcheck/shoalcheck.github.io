How it compares

Shoalcheck, Kubescape, Popeye and Trivy

All four read a Kubernetes cluster and tell you what is wrong with it, and they answer different questions. Shoalcheck is a read-only audit across reliability, security and cost: it prices what it finds and checks a drain, a lost zone or an upgrade before you make the change. The other three are free and open source, and each of them does something Shoalcheck does not.

What this page says about the other tools comes from each project's own README, read on 11 November 2026. Projects move; where a line here has gone stale, the README is right and this page is wrong.

Kubescape

Wider on security, and it runs inside the cluster

Where Kubescape is stronger

  • Checks against NSA-CISA, MITRE ATT&CK and CIS Benchmarks
  • Scans YAML files and Helm charts as well as clusters
  • Finds CVEs in images with Grype and patches them with Copacetic
  • Admission control with Validating Admission Policies, and eBPF runtime monitoring
  • Free, open source, and a CNCF incubating project

Where Shoalcheck differs

  • Reliability and cost in the same reading as security, with the cost in dollars
  • Preflight for a drain, a lost zone or an upgrade
  • Nothing runs in the cluster, at any point
  • No admission control, runtime monitoring or image scanning

Teams that want policy enforcement and runtime detection have it in Kubescape. Shoalcheck answers a different question: what a change will strand, and what the cluster costs.

Popeye

The closest in spirit: read-only, live cluster, free

Where Popeye is stronger

  • Free and open source, with nothing to buy
  • Quick to run, with a report you can dump to HTML
  • Read-only, like Shoalcheck
  • Flags over- and under-allocation when metrics-server is present

Where Shoalcheck differs

  • Cost in dollars, from list prices and from measured usage
  • Preflight for a drain, a lost zone or an upgrade
  • A history of readings, and a comparison of two
  • A CI gate with SARIF, and findings filed in Jira or Linear
  • Each finding names the object it rests on, with its evidence

If Popeye already answers your questions, keep it. Shoalcheck is for the questions that need a dollar figure or a yes-or-no before a change.

Trivy

Almost no overlap: what is in your images, against how the cluster runs them

Where Trivy is stronger

  • Known vulnerabilities in images and dependencies, and SBOMs
  • Secrets and licences in code, and infrastructure-as-code misconfigurations
  • CIS, NSA and Pod Security Standards compliance reports
  • Many targets beyond Kubernetes
  • Free and open source

Where Shoalcheck differs

  • It does not scan images or code at all
  • It reads the running cluster's configuration for reliability, cost and security
  • It never requests Secrets, ConfigMaps or logs
  • Nothing is installed in the cluster

Most teams that run Trivy would run Shoalcheck beside it, not instead of it.

Shoalcheck, in the same terms

What it is, and what it is not

89 detection rules and 15 stack analyzers across reliability, security and cost, and each finding names the object it rests on. It asks with get and list only, installs nothing, and leaves nothing running after the command exits. Every reading counts its own requests and object writes.

It never requests Secrets, ConfigMaps or logs. Run it under the ClusterRole it ships with, and your API server refuses them too — what it reads, line by line.

Preflight answers a drain, a lost zone or an upgrade before you make it: exit 0 when nothing it checks stops the change, 2 when something does, 1 when a read it needed was refused. Around the reading: a CI gate with SARIF, tickets in Jira or Linear, a desktop app, and a document you can hand to someone.

It does not scan images, enforce admission policies, monitor between readings, or change anything in the cluster. Preflight and the size of any reading are free; every finding with its evidence and fix is Pro at $59 a month, and Team and Business cover more clusters — plans and prices.
